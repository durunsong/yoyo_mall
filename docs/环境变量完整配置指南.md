## 🔴 必需的环境变量

这些变量是项目运行的**最低要求**，缺少任何一个都会导致应用无法正常工作。

### 1. 数据库配置

#### `DATABASE_URL`
**用途**: PostgreSQL 数据库连接字符串  
**类型**: 服务端变量  
**必需**: ✅ 是  
**格式**: 
```bash
DATABASE_URL="postgresql://用户名:密码@主机:端口/数据库名?schema=public"
```

**示例**:
```bash
# 本地开发
DATABASE_URL="postgresql://postgres:password@localhost:5432/yoyo_mall"

# 使用 Vercel Postgres
DATABASE_URL="postgres://default:xxxxx@xxx-xxx-xxx.postgres.vercel-storage.com:5432/verceldb"

# 使用 Supabase
DATABASE_URL="postgresql://postgres:xxxxx@db.xxxxx.supabase.co:5432/postgres"

# 使用 Railway
DATABASE_URL="postgresql://postgres:xxxxx@containers-us-west-xxx.railway.app:7777/railway"
```

**获取方式**:
- **Vercel Postgres**: Vercel Dashboard → Storage → Create Database
- **Supabase**: [supabase.com](https://supabase.com) → Project Settings → Database
- **Railway**: [railway.app](https://railway.app) → New Project → PostgreSQL
- **本地**: 安装 PostgreSQL，使用 `psql` 创建数据库

### 2. NextAuth 认证配置

#### `NEXTAUTH_SECRET`
**用途**: NextAuth.js 会话加密密钥  
**类型**: 服务端变量  
**必需**: ✅ 是  
**格式**: 至少 32 字符的随机字符串

**生成命令**:
```bash
# 使用 OpenSSL
openssl rand -base64 32

# 使用 Node.js
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"

# 在线生成
# https://generate-secret.vercel.app/32
```

**示例**:
```bash
NEXTAUTH_SECRET="Xq8mK9pL3rT6vY1wZ4nB7cF0gH2jD5sA8eP1uR4xV7=="
```

#### `NEXTAUTH_URL`
**用途**: NextAuth 认证回调 URL  
**类型**: 服务端变量  
**必需**: ✅ 是（生产环境）  
**格式**: 完整的应用 URL（包含协议）

**示例**:
```bash
# 本地开发
NEXTAUTH_URL="http://localhost:3000"

# 生产环境
NEXTAUTH_URL="https://your-domain.com"

# Vercel 部署
NEXTAUTH_URL="https://your-project.vercel.app"
```

**注意**: Vercel 会自动注入 `VERCEL_URL`，但 NextAuth 需要完整 URL（包含 https://）

## 💳 支付集成

### Stripe 支付（当前版本）

#### `NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY`
**用途**: Stripe 可发布密钥（客户端使用）  
**类型**: 客户端变量  
**必需**: ✅ 是（如果使用支付功能）  
**格式**: `pk_test_` 或 `pk_live_` 开头

**示例**:
```bash
# 测试环境
NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY="pk_test_51Xxxxxxxxxxxxxxxxxxxxx"

# 生产环境
NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY="pk_live_51Xxxxxxxxxxxxxxxxxxxxx"
```

**获取方式**:
1. 访问 [Stripe Dashboard](https://dashboard.stripe.com)
2. 注册/登录账号
3. 开发者 → API 密钥
4. 复制"可发布密钥"

**注意**: 旧版本使用 `NEXT_PUBLIC_STRIPE_PUBLIC_KEY`，建议使用新名称

#### `STRIPE_SECRET_KEY`
**用途**: Stripe 私密密钥（服务端使用）  
**类型**: 服务端变量（⚠️ 敏感信息）  
**必需**: ✅ 是（如果使用支付功能）  
**格式**: `sk_test_` 或 `sk_live_` 开头

**示例**:
```bash
# 测试环境
STRIPE_SECRET_KEY="sk_test_51Xxxxxxxxxxxxxxxxxxxxx"

# 生产环境
STRIPE_SECRET_KEY="sk_live_51Xxxxxxxxxxxxxxxxxxxxx"
```

**获取方式**: 同上，复制"密钥"（Secret key）

**使用位置**:
- `src/lib/stripe.ts` - Stripe 客户端初始化
- `src/app/api/payments/stripe/*.ts` - 支付处理

#### `STRIPE_WEBHOOK_SECRET`
**用途**: Stripe Webhook 签名验证密钥  
**类型**: 服务端变量（⚠️ 敏感信息）  
**必需**: 🟡 推荐（生产环境必需）  
**格式**: `whsec_` 开头

**示例**:
```bash
STRIPE_WEBHOOK_SECRET="whsec_xxxxxxxxxxxxxxxxxxxxx"
```

**获取方式**:
1. Stripe Dashboard → 开发者 → Webhooks
2. 点击"添加端点"
3. 端点 URL: `https://your-domain.com/api/payments/stripe/webhook`
4. 选择要监听的事件（payment_intent.succeeded, payment_intent.payment_failed 等）
5. 复制"签名密钥"

**使用位置**:
- `src/app/api/payments/stripe/webhook/route.ts` - 验证 webhook 签名

## 📧 邮件服务

### Resend（推荐，Newsletter 功能使用）

#### `RESEND_API_KEY`
**用途**: Resend 邮件服务 API 密钥  
**类型**: 服务端变量（⚠️ 敏感信息）  
**必需**: ✅ 是（如果使用 Newsletter）  
**格式**: `re_` 开头

**示例**:
```bash
RESEND_API_KEY="re_123456789_abcdefghijklmnopqrstuvwxyz"
```

**获取方式**:
1. 访问 [Resend](https://resend.com)
2. 注册/登录账号（支持 GitHub 登录）
3. API Keys → Create API Key
4. 复制生成的密钥

**免费额度**: 
- 每月 3,000 封邮件
- 每天 100 封邮件
- 1 个自定义域名

**使用位置**:
- `src/lib/resend.ts` - Resend 客户端初始化
- `src/app/api/newsletter/*.ts` - Newsletter 功能

#### `RESEND_FROM_EMAIL`
**用途**: 邮件发件人地址  
**类型**: 服务端变量  
**必需**: ✅ 是（如果使用 Newsletter）  
**格式**: `Name <email@domain.com>`

**示例**:
```bash
# 测试阶段（仅限发送到你注册的邮箱）
RESEND_FROM_EMAIL="YOYO Mall <onboarding@resend.dev>"

# 生产环境（需要验证域名）
RESEND_FROM_EMAIL="YOYO Mall <noreply@your-domain.com>"
```

**验证自定义域名**:
1. Resend Dashboard → Domains → Add Domain
2. 输入你的域名（如 your-domain.com）
3. 添加 DNS 记录（MX、TXT、CNAME）
4. 等待验证通过（通常几分钟到几小时）
5. 验证后可使用 `name@your-domain.com` 作为发件人

# 使用 OSS 默认域名
NEXT_PUBLIC_OSS_BASE_URL="https://your-bucket.oss-cn-hangzhou.aliyuncs.com"

**使用位置**:

- `src/components/admin/image-upload.tsx` - 图片上传
- `src/app/admin/products/page.tsx` - 商品图片

#### `OSS_REGION`
**用途**: OSS 所在地域  
**类型**: 服务端变量  
**必需**: 🔵 可选（使用 OSS 时必需）

**常用值**:
```bash
OSS_REGION="oss-cn-hangzhou"   # 华东1（杭州）
# OSS_REGION="oss-cn-shanghai"   # 华东2（上海）
# OSS_REGION="oss-cn-beijing"    # 华北2（北京）
# OSS_REGION="oss-cn-shenzhen"   # 华南1（深圳）
# OSS_REGION="oss-cn-hongkong"   # 香港
```

#### `OSS_ACCESS_KEY_ID`
**用途**: 阿里云访问密钥 ID  
**类型**: 服务端变量（⚠️ 敏感信息）  
**必需**: 🔵 可选（使用 OSS 时必需）

**获取方式**:
1. 登录 [阿里云控制台](https://ram.console.aliyun.com/users)
2. 访问控制 RAM → 用户 → 创建用户
3. 勾选"Open API 调用访问"
4. 保存 AccessKey ID 和 AccessKey Secret
5. 添加权限：AliyunOSSFullAccess

**示例**:
```bash
OSS_ACCESS_KEY_ID="LTAI5txxxxxxxxxxxxx"
```

#### `OSS_ACCESS_KEY_SECRET`
**用途**: 阿里云访问密钥 Secret  
**类型**: 服务端变量（⚠️ 敏感信息）  
**必需**: 🔵 可选（使用 OSS 时必需）

**示例**:
```bash
OSS_ACCESS_KEY_SECRET="your_secret_key_xxxxxxxxxxxxx"
```

#### `OSS_BUCKET`
**用途**: OSS Bucket 名称  
**类型**: 服务端变量  
**必需**: 🔵 可选（使用 OSS 时必需）

**示例**:
```bash
OSS_BUCKET="yoyo-mall-images"
```

**创建 Bucket**:
1. OSS 控制台 → Bucket 列表 → 创建 Bucket
2. 名称：yoyo-mall-images（需全局唯一）
3. 地域：选择与应用相同或相近的地域
4. 读写权限：公共读（图片需要公开访问）
5. 创建后记录 Bucket 名称

#### `OSS_ENDPOINT`
**用途**: OSS 服务端点  
**类型**: 服务端变量  
**必需**: 🔵 可选（使用 OSS 时必需）

**示例**:
```bash
OSS_ENDPOINT="https://oss-cn-hangzhou.aliyuncs.com"
```

**对应关系**:
- `oss-cn-hangzhou` → `https://oss-cn-hangzhou.aliyuncs.com`
- `oss-cn-shanghai` → `https://oss-cn-shanghai.aliyuncs.com`
- `oss-cn-beijing` → `https://oss-cn-beijing.aliyuncs.com`

#### `OSS_FOLDER`
**用途**: OSS 中的文件夹前缀  
**类型**: 服务端/客户端共用  
**必需**: 🔵 可选  
**默认值**: "yoyo_mall"

**示例**:
```bash
OSS_FOLDER="yoyo_mall"
# OSS_FOLDER="root"  # 不使用文件夹
```

**使用位置**:
- `src/lib/oss-images.ts` - 图片路径前缀

## ❓ 常见问题

### Q1: 为什么有些变量有 `NEXT_PUBLIC_` 前缀？

**A**: 
- 有前缀：可以在浏览器端访问（客户端变量）
- 无前缀：只能在服务端访问（更安全，适合敏感信息）

**注意**: 所有敏感信息（密钥、密码等）都不应该加 `NEXT_PUBLIC_` 前缀！

---

### Q2: 本地开发需要配置所有变量吗？

**A**: 不需要。最小配置只需要：
- `DATABASE_URL`
- `NEXTAUTH_SECRET`
- `NEXTAUTH_URL`

其他功能会使用默认值或跳过。

---

### Q3: 如何生成 NEXTAUTH_SECRET？

**A**: 使用以下任一方法：

```bash
# 方法1: OpenSSL
openssl rand -base64 32

# 方法2: Node.js
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"

# 方法3: 在线生成
# 访问 https://generate-secret.vercel.app/32
```

---

### Q4: Vercel 部署时如何配置环境变量？

**A**: 
1. Vercel Dashboard → 选择项目
2. Settings → Environment Variables
3. 添加变量，选择环境（Production/Preview/Development）
4. 保存后重新部署

**重要**: 
- 敏感信息只在 Vercel Dashboard 配置，不要提交到代码
- 修改环境变量后需要重新部署才能生效

---

### Q5: 为什么购物车功能报错？

**A**: 检查以下配置：
1. `DATABASE_URL` 是否正确
2. `NEXTAUTH_URL` 是否匹配实际域名
3. 是否已运行数据库迁移：`npx prisma db push`
4. 查看 Vercel 日志排查具体错误

---

### Q6: 如何测试 Stripe 支付？

**A**: 
1. 使用测试密钥（`pk_test_` 和 `sk_test_`）
2. 使用 Stripe 测试卡号：
   - 成功：`4242 4242 4242 4242`
   - 失败：`4000 0000 0000 0002`
   - 其他测试卡：https://stripe.com/docs/testing

---

### Q7: Newsletter 功能发不出邮件？

**A**: 检查：
1. `RESEND_API_KEY` 是否正确
2. `RESEND_FROM_EMAIL` 格式是否正确
3. 测试阶段只能发送到你注册 Resend 的邮箱
4. 生产环境需要验证自定义域名

---

### Q8: 如何在 Vercel 中使用 PostgreSQL？

**A**: 
1. **方式一**: Vercel Postgres
   - Vercel Dashboard → Storage → Create Database
   - 自动注入 `DATABASE_URL`

2. **方式二**: 外部数据库
   - [Supabase](https://supabase.com)（推荐，免费）
   - [Railway](https://railway.app)
   - [Neon](https://neon.tech)

---

### Q9: 如何隐藏环境变量不被提交到 Git？

**A**: 
1. `.env.local` 文件已在 `.gitignore` 中，不会被提交
2. 永远不要在代码中硬编码敏感信息
3. 使用 `.env.example` 作为模板，不包含真实值

---

### Q10: 生产环境如何创建管理员账号？

**A**: 
1. 配置 `SEED_ADMIN_SECRET`
2. 使用 API 创建：

```bash
curl -X POST https://your-domain.com/api/admin/create-admin \
  -H "Content-Type: application/json" \
  -H "x-seed-secret: your-secret-key" \
  -d '{
    "email": "admin@example.com",
    "password": "secure-password",
    "name": "Admin"
  }'
```
