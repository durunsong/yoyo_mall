## 🔧 详细修复说明

### 1. 修复购物车和心愿单数据持久化问题

**文件**: `src/components/layout/floating-toolbar.tsx`

**问题根因**:
- Zustand的localStorage持久化在服务端渲染(SSR)时无法读取
- 客户端hydration时存在数据不同步问题
- 刷新页面后，购物车和心愿单角标归零

**修复方案**:

#### 1) 添加客户端挂载标记
```typescript
const [mounted, setMounted] = useState(false); // 确保客户端已挂载

// 确保组件已在客户端挂载
useEffect(() => {
  setMounted(true);
  setIsClient(true);
  setCurrentTime(new Date());
  // ...
}, []);
```

#### 2) 条件计算数量，避免SSR不一致
```typescript
// 购物车数量 - 只在客户端渲染后计算
const cartCount = mounted 
  ? items.reduce((total, item) => total + item.quantity, 0) 
  : 0;

// 心愿单数量 - 只在客户端渲染后计算
const wishlistCount = mounted 
  ? wishlistItems.length 
  : 0;
```

**技术原理**:
- **Hydration Mismatch**: Next.js的SSR会先在服务端渲染，再在客户端"注水"(hydration)
- **localStorage只在客户端可用**: 服务端无法访问浏览器的localStorage
- **解决方案**: 通过`mounted`状态确保只在客户端挂载后才读取和显示localStorage数据

**效果**:
- ✅ 刷新页面后购物车角标正确显示
- ✅ 心愿单角标数据持久化
- ✅ 避免SSR/CSR数据不一致的警告

### 2. 修复消息图标角标不显示问题

**文件**: `src/components/layout/user-notifications.tsx`

**问题根因**:
- 通知数据只在用户点击图标(`open`为true)时才加载
- 页面首次加载时角标为0，给用户错觉"没有通知"

**修复方案**:

#### 1) 添加客户端挂载标记
```typescript
const [mounted, setMounted] = useState(false);

useEffect(() => {
  setMounted(true);
}, []);
```

#### 2) 页面加载时立即获取通知数据
```typescript
// 修改前: 依赖open状态
useEffect(() => {
  if (session?.user && open) {
    // 加载通知...
  }
}, [session, open]);

// 修改后: 页面加载就获取
useEffect(() => {
  if (session?.user && mounted) {
    const mockNotifications: Notification[] = [
      {
        id: '1',
        type: 'order',
        title: '订单已发货',
        message: '您的订单 #12345 已发货，预计3天内送达',
        read: false,
        // ...
      },
      // 更多通知...
    ];
    setNotifications(mockNotifications);
  }
}, [session, mounted]); // 不再依赖open
```

**优化点**:
1. **即时显示**: 用户登录后立即看到未读通知数量
2. **用户体验**: 红色角标引导用户点击查看
3. **性能优化**: 通知数据预加载，点击时立即显示

**效果**:
- ✅ 页面加载时角标立即显示
- ✅ 未读数量准确显示（如："2"）
- ✅ 点击图标无需等待加载
