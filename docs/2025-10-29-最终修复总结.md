## 🐛 Bug 修复

### 1. Analytics API - UserRole 枚举错误

**问题**: 使用了不存在的 `GUEST` 角色,导致 500 错误

**修复位置**:
- 总用户数统计 (第 82-87 行)
- 最近 N 天新用户 (第 133-145 行)
- 上期用户数统计 (第 281-289 行)

**修复方案**:
```typescript
// ❌ 修复前
role: {
  in: ['CUSTOMER', 'GUEST']  // GUEST 不存在!
}

// ✅ 修复后
role: 'CUSTOMER'  // 只统计普通用户
```

**影响**: Analytics API 现在可以正常返回数据,数据分析页面正常显示

---

### 2. Notifications API - 数据库字段错误

**问题**: 使用了不存在的 `stock` 和 `published` 字段

**修复方案**:
```typescript
// ❌ 修复前
where: {
  published: true,
  stock: { lte: 10 }
}

// ✅ 修复后
where: {
  status: 'PUBLISHED',
  inventory: {
    quantity: { lte: 10 }
  }
}
```

**影响**: 通知 API 可以正确查询低库存商品

---

### 3. Orders API - 参数验证过于严格

**问题**: 必填参数导致前端调用失败

**修复方案**:
```typescript
// ✅ 所有参数都改为可选
const orderQuerySchema = z.object({
  page: z.coerce.number().min(1).optional().default(1),
  limit: z.coerce.number().min(1).max(100).optional().default(20),
  status: z.enum([...]).optional().nullable(),
  sortBy: z.enum([...]).optional().default('createdAt'),
  sortOrder: z.enum(['asc', 'desc']).optional().default('desc'),
});
```

**影响**: 订单 API 调用更加灵活,不再报验证错误

---

### 4. 购物车页面 - 未定义变量

**问题**: `loading` 变量未定义但被使用

**修复方案**:
```typescript
// 移除未使用的 loading 状态
// const [loading, setLoading] = useState(false);

// 简化按钮禁用逻辑
disabled={items.length === 0}
```

**影响**: 购物车页面不再报错
