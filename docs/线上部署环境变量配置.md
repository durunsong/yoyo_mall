# 线上部署环境变量配置指南

## 问题说明

在部署到 Vercel 或其他线上环境时，需要正确配置环境变量，避免使用硬编码的 `localhost:3000`。

## 必需的环境变量

### 1. NEXT_PUBLIC_APP_URL
应用的完整 URL，用于 metadata、sitemap 等。

**本地开发：**
```
NEXT_PUBLIC_APP_URL=http://localhost:3000
```

**Vercel 部署：**
```
NEXT_PUBLIC_APP_URL=https://your-domain.vercel.app
```

### 2. NEXTAUTH_URL
NextAuth 认证服务的 URL。

**本地开发：**
```
NEXTAUTH_URL=http://localhost:3000
```

**Vercel 部署：**
```
NEXTAUTH_URL=https://your-domain.vercel.app
```

**重要提示：** Vercel 会自动注入 `VERCEL_URL` 环境变量，但 NextAuth 需要完整的 URL（包括协议）。

### 3. NEXT_PUBLIC_BASE_URL
基础 URL，用于 sitemap 和 robots.txt。

**本地开发：**
```
NEXT_PUBLIC_BASE_URL=http://localhost:3000
```

**Vercel 部署：**
```
NEXT_PUBLIC_BASE_URL=https://your-domain.vercel.app
```

## Vercel 环境变量配置步骤

### 方式一：通过 Vercel Dashboard 配置

1. 登录 Vercel Dashboard
2. 选择你的项目
3. 进入 "Settings" → "Environment Variables"
4. 添加以下环境变量：

| 变量名 | 值 | 环境 |
|--------|-----|------|
| NEXT_PUBLIC_APP_URL | https://your-domain.vercel.app | Production, Preview, Development |
| NEXTAUTH_URL | https://your-domain.vercel.app | Production, Preview, Development |
| NEXT_PUBLIC_BASE_URL | https://your-domain.vercel.app | Production, Preview, Development |
| DATABASE_URL | postgresql://... | Production, Preview, Development |
| NEXTAUTH_SECRET | your-secret-key | Production, Preview, Development |

5. 保存后重新部署项目

### 方式二：通过 vercel.json 配置

在项目根目录创建或编辑 `vercel.json`：

```json
{
  "env": {
    "NEXT_PUBLIC_APP_URL": "https://your-domain.vercel.app",
    "NEXTAUTH_URL": "https://your-domain.vercel.app",
    "NEXT_PUBLIC_BASE_URL": "https://your-domain.vercel.app"
  }
}
```

**注意：** 敏感信息（如 DATABASE_URL、NEXTAUTH_SECRET）不要放在 vercel.json 中，应该通过 Dashboard 配置。

## 代码修复说明

### 修复 1: src/app/layout.tsx

**修复前：**
```typescript
metadataBase: new URL(
  process.env.NEXT_PUBLIC_APP_URL || 'http://localhost:3000',
),
```

**修复后：**
```typescript
// 动态获取应用URL，优先使用环境变量，其次使用 Vercel URL，最后才用 localhost
metadataBase: new URL(
  process.env.NEXT_PUBLIC_APP_URL || 
  process.env.VERCEL_URL ? `https://${process.env.VERCEL_URL}` : 'http://localhost:3000'
),
```

### 修复 2: src/app/api/auth/[...nextauth]/route.ts

**修复前：**
```typescript
// 动态配置URL，支持线上环境
...(process.env.NEXTAUTH_URL && process.env.NEXTAUTH_URL !== 'http://localhost:3000' 
  ? {} 
  : { 
      pages: {
        signIn: '/',
        signOut: '/',
      },
    }
),
```

**修复后：**
```typescript
// 自定义登录和登出页面
pages: {
  signIn: '/',
  signOut: '/',
},
```

### 修复 3: 购物车 API 错误日志增强

在 `src/app/api/cart/route.ts` 中增加了详细的错误日志，方便排查线上问题：

- 记录请求开始
- 记录认证状态
- 记录请求参数
- 记录商品查询结果
- 记录详细的错误信息（包括 Prisma 错误代码）

## 常见问题排查

### 问题 1: 购物车添加失败，返回 500 错误

**可能原因：**
1. 数据库连接失败
2. 认证状态异常
3. 商品不存在或状态不正确

**排查方法：**
查看 Vercel 日志（Vercel Dashboard → 项目 → Functions → 日志），查找以下日志：
- `购物车API - 开始处理添加请求`
- `购物车API - 认证状态`
- `购物车API - 请求参数`
- `购物车API - 商品查询结果`
- `添加到购物车失败 - 详细错误信息`

### 问题 2: 认证回调 URL 错误

如果看到 `authjs.callback-url=http://localhost:3000`，说明：
1. 环境变量 `NEXTAUTH_URL` 未正确配置
2. 需要在 Vercel 中设置正确的 URL
3. 设置后需要清除浏览器 Cookie 重新登录

### 问题 3: 图片或资源加载失败

检查以下环境变量是否配置：
- `NEXT_PUBLIC_APP_URL`
- `NEXT_PUBLIC_BASE_URL`

- [ ] 测试购物车功能

## 推荐的环境变量完整列表

```bash
# 应用 URL
NEXT_PUBLIC_APP_URL=https://your-domain.vercel.app
NEXT_PUBLIC_BASE_URL=https://your-domain.vercel.app

# NextAuth 配置
NEXTAUTH_URL=https://your-domain.vercel.app
NEXTAUTH_SECRET=your-super-secret-key

# 数据库
DATABASE_URL=postgresql://...

# Stripe
NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY=pk_live_...
STRIPE_SECRET_KEY=sk_live_...
STRIPE_WEBHOOK_SECRET=whsec_...

# Google OAuth (可选)
GOOGLE_CLIENT_ID=...
GOOGLE_CLIENT_SECRET=...

# OSS (可选)
OSS_REGION=...
OSS_ACCESS_KEY_ID=...
OSS_ACCESS_KEY_SECRET=...
OSS_BUCKET=...
OSS_ENDPOINT=...
```

## 注意事项

1. **永远不要在代码中硬编码 localhost:3000**
2. **所有需要在浏览器端访问的 URL 都要加 `NEXT_PUBLIC_` 前缀**
3. **敏感信息只通过 Vercel Dashboard 配置，不要提交到代码仓库**
4. **部署后记得清除浏览器 Cookie 重新测试**
5. **善用 Vercel 的日志功能排查问题**
