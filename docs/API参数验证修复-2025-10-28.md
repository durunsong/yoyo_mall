## 问题描述

```json

      "message": "Expected 'name' | 'sortOrder' | 'createdAt', received null"

      "received": "null",
      "code": "invalid_type",
      "path": ["sortOrder"],
      "message": "Expected 'asc' | 'desc', received null"
    }
  ]
}
```

## 根本原因

### 问题分析

1. **URL参数处理不当**:
   ```typescript
   // ❌ 错误：searchParams.get() 对于不存在的参数返回 null
   const query = categoryQuerySchema.parse({
     parentId: searchParams.get('parentId'),      // null
     sortBy: searchParams.get('sortBy'),          // null
     sortOrder: searchParams.get('sortOrder'),    // null
   });
   ```

2. **Zod Schema 不支持 null**:
   ```typescript
   // ❌ 错误：不接受 null 值
   const categoryQuerySchema = z.object({
     parentId: z.string().optional(),        // 只接受 string | undefined
     sortBy: z.enum([...]).default('sortOrder'),
     sortOrder: z.enum([...]).default('asc'),
   });
   ```

### 为什么会这样？

在JavaScript中：
- `searchParams.get('key')` 对于不存在的key返回 `null`
- Zod的 `.optional()` 只接受 `undefined`，不接受 `null`
- 直接传递 `null` 会导致验证失败

## 修复方案

### 方案1：修改Schema支持null（已采用）

```typescript
// ✅ 正确：同时支持 null 和 undefined
const categoryQuerySchema = z.object({
  includeProducts: z.coerce.boolean().default(false),
  parentId: z.string().nullable().optional(),
  isActive: z.coerce.boolean().optional(),
  sortBy: z.enum(['name', 'sortOrder', 'createdAt']).nullable().default('sortOrder'),
  sortOrder: z.enum(['asc', 'desc']).nullable().default('asc'),
});
```

### 方案2：参数预处理

```typescript
// ✅ 正确：只传递存在的参数
const params: any = {};
const includeProducts = searchParams.get('includeProducts');
const parentId = searchParams.get('parentId');
const isActive = searchParams.get('isActive');
const sortBy = searchParams.get('sortBy');
const sortOrder = searchParams.get('sortOrder');

if (includeProducts !== null) params.includeProducts = includeProducts;
if (parentId !== null) params.parentId = parentId;
if (isActive !== null) params.isActive = isActive;
if (sortBy !== null) params.sortBy = sortBy;
if (sortOrder !== null) params.sortOrder = sortOrder;

const query = categoryQuerySchema.parse(params);
```

### 方案3：使用 searchParams.has()（最佳实践）

```typescript
// ✅ 最佳：检查参数是否存在
const rawQuery: any = {};

if (searchParams.has('page')) rawQuery.page = searchParams.get('page');
if (searchParams.has('limit')) rawQuery.limit = searchParams.get('limit');
```

## Zod参数处理最佳实践

### 1. 处理可选参数

```typescript
// ❌ 错误：不处理 null
z.string().optional()

// ✅ 正确：同时处理 null 和 undefined
z.string().nullable().optional()

// ✅ 或者使用预处理
z.preprocess(
  (val) => val === null ? undefined : val,
  z.string().optional()
)
```

### 2. 处理枚举类型

```typescript
// ❌ 错误
z.enum(['asc', 'desc']).default('asc')

// ✅ 正确：支持 null
z.enum(['asc', 'desc']).nullable().default('asc')

// ✅ 或者使用 optional
z.enum(['asc', 'desc']).optional().default('asc')
```

### 3. 处理布尔值

```typescript
// ❌ 错误：字符串 "true" 不会转换
z.boolean().optional()

// ✅ 正确：自动转换字符串
z.coerce.boolean().optional()

// ✅ 或者自定义转换
z.preprocess(
  (val) => val === 'true' || val === true,
  z.boolean()
)
```

### 4. 处理数字

```typescript
// ❌ 错误：字符串 "123" 不会转换
z.number().min(0).optional()

// ✅ 正确：自动转换字符串
z.coerce.number().min(0).optional()
```

## 通用修复模板

对于所有使用 Zod 验证 URL 参数的API，使用以下模板：

```typescript
export async function GET(request: NextRequest) {
  try {
    const { searchParams } = new URL(request.url);
    
    // 方案1：使用 has() 检查（推荐）
    const rawQuery: any = {};
    if (searchParams.has('param1')) rawQuery.param1 = searchParams.get('param1');
    if (searchParams.has('param2')) rawQuery.param2 = searchParams.get('param2');
    
    const query = schema.parse(rawQuery);
    
    // 方案2：Schema 支持 nullable
    const query = schema.parse({
      param1: searchParams.get('param1'), // 可以是 null
      param2: searchParams.get('param2'),
    });
    
    // ... 业务逻辑
  } catch (error) {
    if (error instanceof z.ZodError) {
      return NextResponse.json({
        success: false,
        error: 'VALIDATION_ERROR',
        message: '请求参数无效',
        details: error.errors,
      }, { status: 400 });
    }
    // ...
  }
}
```

对应的Schema定义：

```typescript
// 方案1：optional + default
const schema = z.object({
  param1: z.string().optional(),
  param2: z.enum(['a', 'b']).optional().default('a'),
});

// 方案2：nullable + optional
const schema = z.object({
  param1: z.string().nullable().optional(),
  param2: z.enum(['a', 'b']).nullable().default('a'),
});
```

## 经验教训

1. **URL参数总是字符串或null**
   - 永远不要假设参数存在
   - 使用 `searchParams.has()` 或 `nullable()`

2. **Zod的 optional() 不接受 null**
   - 需要同时使用 `.nullable().optional()`
   - 或者使用 `preprocess` 转换

3. **默认值的处理**
   - `.default()` 只在值为 `undefined` 时生效
   - 如果传入 `null`，需要先转换为 `undefined`

4. **类型转换**
   - 使用 `z.coerce.*` 自动转换字符串
   - 布尔值：`z.coerce.boolean()`
   - 数字：`z.coerce.number()`

5. **错误处理**
   - 总是捕获 `ZodError` 并返回友好的错误信息
   - 在开发环境记录详细的 `error.errors`
